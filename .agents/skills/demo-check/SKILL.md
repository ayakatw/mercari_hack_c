# demo-check

デモ・発表の直前に通す確認手順。**発表当日の朝と、録画の直前に必ず実行する。**

所要 15〜20 分。上から順に実行し、**落ちた項目は直すか、直せないなら発表者に伝える。**

## 0. 前提（このアプリ固有）

- **install も build も存在しない。** `npm install` / `npm run build` は無い。clean install の確認は「clone 直後の状態で開けるか」に読み替える
- **ライブ AI 呼び出しは無い。** 認識結果は `data.js` の `AI_RESULTS` に焼き込み済み。API の失敗・遅延・レート制限はデモ中に発生しない（[docs/API.md](../../../docs/API.md)）
- **リロードすると必ずチュートリアルから始まる。** 永続化していないため、デモは何度でも同じ手順でやり直せる

---

## 1. クリーンな状態で開けるか

```bash
# 追跡されているファイルだけで動くことを確認する
git status --porcelain          # 未コミットの変更が無いか
git stash list                  # 退避したまま忘れていないか

# 別ディレクトリに clone して開く（発表用 PC を想定）
cd /tmp && rm -rf demo-check && git clone <repo-url> demo-check && cd demo-check
python3 -m http.server 5173
```

- [ ] http://localhost:5173 でチュートリアルの最初の画面が出る
- [ ] `open index.html`（`file://` 直開き）でも同じく動く ← **会場でサーバを立てられない場合の保険**

## 2. 静的チェック

```bash
node --check data.js && for f in js/*.js; do node --check "$f" || echo "NG: $f"; done && echo OK

grep -ohE "assets/img/[A-Za-z0-9_.-]+" index.html data.js js/*.js styles.css \
  | sort -u | while read -r p; do [ -f "$p" ] || echo "MISSING: $p"; done
```

- [ ] 構文エラーなし（`OK` が出る）
- [ ] `MISSING:` が 1 件も出ない ← **画像切れはデモで最も目立つ事故**

## 3. デモの核（絶対に通す）

台本どおりの操作を最初から最後まで 1 回通す。

- [ ] チュートリアル: ようこそ → 祭壇写真を選択 → 解析スピナー → 認識リスト 7 件
- [ ] **缶バッジの ＋ を 1 回押す** → 合計が **¥81,000** になり「この内容で確定」が有効化される
- [ ] 「あなたの祭壇は ¥81,000 です」→ 資産タブへ着地
- [ ] ホーム TL: 8 件表示 / いいねで数が増えハートが赤くなる / 「譲ります」投稿の「欲しい」でトースト / みお のアイコンからプロフィールへ
- [ ] 投稿タブ: 画像選択 → 解析 → AI 結果カード（相場 ¥3,200）→ 投稿 → 「+¥3,200」
- [ ] **投稿直後に「2個目を検出」通知カードが出る** ← デモのハイライト
- [ ] 「出品ドラフトを見る」→ メルカリ配色の出品モック、全項目プレフィル済み
- [ ] 「出品する」→ 完了画面 → 資産タブに戻ると該当アイテムに「出品中」バッジ
- [ ] 資産タブ: 総額 **¥84,200** / 30 日チャートが描画される / 8/21 の急騰マーカー / 重複アイテムに「×2」バッジ
- [ ] ステラのトレカの行タップで詳細モーダル（他の行はタップ無効でよい）
- [ ] マイページ: 祭壇カードを作る → モーダル → Xでシェアでトースト

## 4. 状態の確認（loading / empty / error）

- [ ] **loading**: チュートリアルと投稿の「AI が解析中…」スピナーが約 1.5 秒出て、必ず次へ進む（止まらない）
- [ ] **empty**: マイページのグリッドが、投稿前でも崩れずに表示される
- [ ] **error**: チュートリアルで缶バッジを直さずに「この内容で確定」→ トーストが出て**画面が壊れない**
- [ ] **既知の落とし穴**: 缶バッジ**以外**の個数を増やすと、缶バッジを 2 個にしてもトーストが出続けて進めなくなる（[docs/DECISIONS.md](../../../docs/DECISIONS.md) 参照）。**デモ中に余計な ＋ を押さないこと**を発表者に伝える
- [ ] トーストが 3.2 秒で自動的に消える

## 5. ネットワーク障害耐性 ← 会場で最も起きやすい

外部依存は CDN 2 本（Chart.js / Tailwind）のみ。DevTools の Network タブで **Offline** にしてリロードし、確認する。

- [ ] **Offline にしてリロードしても全画面が表示される**（ローカルファイルのみで動くため）
- [ ] 資産タブのチャートが**フォールバック描画**に切り替わる（Chart.js が読めないとき `screen-assets.js` の `drawFallback` が Canvas 2D で簡易ラインを描く）
- [ ] Tailwind CDN が読めないときにレイアウトが崩れないか **← 未検証。必ず目視すること**（Tailwind は実質未使用だが Preflight リセットを注入するため、外れると見た目が変わる可能性がある）

崩れる場合の対処: 会場ではネットに繋がない前提にせず、**事前にオフラインで通し練習しておく**。または Chart.js / Tailwind をローカルに落として `index.html` の参照を差し替える（要件定義書 §6 は CDN 前提だが、AGENTS 由来の「外部通信を発生させない」方針とはここが食い違っている）。

## 6. Console にエラーが出ていないか

DevTools の Console を開いたまま、3 章の全操作をもう一度通す。

- [ ] 赤いエラーが 0 件
- [ ] `Uncaught TypeError` が出ていない（`getItem` の null 未ガードで出やすい）
- [ ] 画像の 404 が出ていない

## 7. 表示の確認

- [ ] 発表に使う**実際の PC・ブラウザ**で開く（普段と別のマシンなら必ず事前に）
- [ ] 390×844 のスマホ枠が画面中央に収まる。**発表時の画面解像度・拡大率で確認する**（プロジェクタ投影時に枠がはみ出ないか）
- [ ] ブラウザのズームが 100% になっている
- [ ] フォントが崩れていない（`styles.css` はシステムフォント指定。Web フォントは使っていない）

## 8. secret の確認

```bash
git ls-files | xargs grep -lniE 'api[_-]?key|secret|token|password|ghp_|sk-' 2>/dev/null
git log --oneline --all -- .env
git status --porcelain | grep -E '\.env|node_modules|server/'
```

- [ ] 追跡ファイルに API キー・トークンが含まれていない
- [ ] `.env` がコミットされていない（`.gitignore` 済み）
- [ ] `node_modules/` / `server/` がコミットされていない
- [ ] **画面共有する DevTools・ターミナルにトークンが表示される状態になっていない**（`git remote -v` に埋め込まれた token など）

## 9. 環境変数

- [ ] **このアプリは環境変数を必要としない。** `.env` が無くても完全に動くことを確認する（`.env` を一時的にリネームして起動する）

## 落ちたときの縮退手順

時間が無いときに捨てる順（要件定義書 §7 のスコープカット順）。

1. 祭壇カードモーダル → 静止画 1 枚で代替
2. 簡易プロフィール → アイコンタップを使わない
3. アイテム詳細モーダル → 資産タブのメインチャートのみ見せる
4. チュートリアル → 録画内のスライドで代替

**最後まで守る核**: 投稿 → 2個目通知 → 出品モック、資産タブ、ホーム TL。

## 報告

確認した項目・落ちた項目・**未確認のまま残した項目**を分けて書く。ブラウザで見ていない項目を「OK」と書かない。
