# LISTING-DESIGN

出品モック（`js/screen-listing.js` + `styles.css` の `/* Mercari listing */` セクション）のデザイン仕様。

2026-09-01 に、自作の赤ヘッダー版から**実物メルカリの出品画面の完コピ**へ作り替えた。判断の理由は [DECISIONS.md](DECISIONS.md) の「出品モックを実物メルカリのダークUIに完コピし、赤ヘッダーを廃止する」、要件は [../specs/推しポート要件定義.md](../specs/推しポート要件定義.md) §2.6 を参照。**本ドキュメントは実装の詳細であり、仕様の正ではない。**

## 2. 完コピの範囲

**レイアウト・配色・UIパーツは実物どおり。値は必ず埋める。**

実物は全項目が空のプレースホルダ（商品名「40字以内、例) メルカリTシャツ」、カテゴリー「必須 ＞」、販売価格「¥300~」など）。これを字義どおり完コピすると、仕様書 §2.6 の核である「全項目プレフィル済み」＝ AI が自動入力済みという主張が画面から消える。

したがって**空欄を再現してはいけない**。審査員（メルカリ社員）はあの空欄だらけの画面を見慣れているので、同じレイアウトで全部埋まっていることが差分そのものになる。

| 位置 | 実物 | 推しポート |
| --- | --- | --- |
| 商品名 | 「40字以内、例) メルカリTシャツ」 | ステラ アクリルスタンド |
| カテゴリー | 「必須」（グレー） | タレントグッズ > アクリルスタンド |
| 商品の状態 | 「必須」（グレー） | 未開封 |
| 商品の説明 | 「1,000字以内、例) …」 | AI生成風の説明文 |
| 販売価格 | 「¥300~」（グレー） | ¥3,200 |
| 販売手数料 | 「-」 | −¥320 |
| 販売利益 | 「-」 | ¥2,880 |

## 3. デザイントークン

`styles.css` の `.mercari-runtime` に CSS 変数として定義している。**値はスクショからの目視推定**であり、公式のデザイントークンではない。

| 変数 | 値 | 用途 |
| --- | --- | --- |
| `--ml-bg` | `#1c1c1e` | 画面背景・ヘッダー・ステータスバー・ホームインジケータ |
| `--ml-line` | `#2c2c2e` | セクション間の区切り線 |
| `--ml-border` | `#48484a` | 入力欄・テンプレートボタン・未選択カードの枠線 |
| `--ml-text` | `#f2f2f7` | 見出し・本文・入力値 |
| `--ml-dim` | `#8e8e93` | 補助テキスト・chevron・未選択ラジオ |
| `--ml-pill` | `#3a3a3c` | ピル型バッジ背景・×ボタンの円 |
| `--ml-pill-text` | `#aeaeb2` | ピル型バッジの文字 |
| `--ml-coral` | `#f2705f` | フッター2ボタン（ダーク側の赤。**メルカリ赤ではない**） |
| `--ml-blue` | `#0a84ff` | 選択中ラジオと選択カードの枠線 |
| `--ml-link` | `#4a9eff` | 規約リンク |
| `--ml-sel` | `#242426` | 選択中カードの内部背景 |

完了画面（ライト）は変数を使わず直値。背景 `#101012`、カード `#fff`、見出し `#1a1a1a`、補助 `#6c6c6c`、赤 `#f5313b`。

### 赤の流れ

ダークモードのフォームには**メルカリ赤（`#ff0211`）が出てこない**。実物のダークUIのボタンはコーラル寄り（`#f2705f`）だからで、これは完コピの結果として意図的にそうなっている。赤は次の順で立ち上がる。

```
フォーム（コーラル #f2705f）→ 完了画面（鮮赤 #f5313b）→ グッズ一覧タブの「出品中」バッジ（#ff0211）
```

**`--mercari` 変数（`#ff0211`）の値は絶対に変更しないこと。** グッズ一覧タブの `.listed-badge`（`js/screen-goods.js`）が同じ変数を参照しているため、値を変えると無関係な画面が道連れになる。

### 4.2 出品完了（ライト・モーダル風の全画面）

実物はモーダルだが、**推しポートでは全画面の1ページとして実装している**（`state.listing.stage === 'success'` で差し替え）。背後に何を敷くかの分岐を持たずに済むため。見た目だけモーダルに寄せている。

- 💐（絵文字。実物は花束を持つ手のイラスト）
- 「出品が完了しました」
- 「売れたら売上金は**推しポート**に反映されます」（実物にない。仕様書 §2.6 の明記事項）
- ボタン3段階（塗り／枠線／テキストのみ）。**文言は3つとも実物どおり**

| ボタン | スタイル | 遷移 | 差分 |
| --- | --- | --- | --- |
| 出品した商品をみる | 塗り（`#f5313b`） | `finishListing()` → グッズ一覧タブ | **実物では「続けて出品する」が塗り。デモの着地がグッズ一覧タブのため順序のみ入れ替えた** |
| 続けて出品する | 枠線 | `prepareListing()` → フォームへ戻る | なし |
| 商品をシェアする | テキストのみ | トースト | なし |

## 5. タップの受け皿

**遷移しない要素は無反応にせず、必ずトーストで受ける。** ブースで審査員が実物を触るため（仕様書 §4.2）、押せそうで何も起きない要素はその場で事故になる。

| 要素 | トースト文言 |
| --- | --- |
| テンプレート | テンプレート入力はデモでは省略しています |
| カテゴリー / 商品の状態 / 配送方法 の行 | 推しポートが入力済みです。そのまま出品できます |
| 下書きに保存 | 下書きに保存しました（デモ） |
| 商品をシェアする | 商品のリンクをコピーしました（デモ） |

chevron 行のトーストは、触られたときに**むしろプレフィル済みという売りを説明する**文言にしてある。

## 6. 共通クロームへの影響

listing 画面は `js/router.js` が `.app-runtime` に `mercari-runtime` クラスを、ステータスバーに `mercari-status` クラスを付けることで出し分けている（この分岐自体は既存で、今回変更していない）。ダーク化に伴い CSS 側を2箇所直した。

| セレクタ | 変更 | 理由 |
| --- | --- | --- |
| `.status-bar.mercari-status` | 白背景・黒文字 → `#1c1c1e` 背景・`#f2f2f7` 文字 | 黒画面の上に白い帯が残るため |
| `.mercari-runtime .home-indicator` | **新規追加**（`#1c1c1e`、バーは `#5b5b60`） | `.home-indicator` は route スコープが無く `background: #fff` 固定だった。画面最下部に幅いっぱいの白帯が残る |

`.phone-frame`（ベゼル `#29283d`）は画面内容と独立しているため影響なし。

## 7. クラス名の対応（旧 → 新）

旧実装はフォーム（ダークにしたい）と完了画面（ライトのまま残したい）が**同じクラスを共有していた**ため、ベースクラスを上書きすると完了画面まで道連れでダークになる構造だった。これを解消するため `.ml-*` 系に作り替えている。

| 旧 | 新 |
| --- | --- |
| `.mercari-header` | `.ml-header` / `.ml-close`（完了画面はヘッダーを持たない） |
| `.external-banner` | **廃止**（実物にない） |
| `.listing-section` / `.photo-section` | `.ml-block` / `.ml-photos` |
| `.listing-field` | `.ml-input` / `.ml-textarea` / `.ml-row` 系 |
| `.listing-photo` | `.ml-slot` / `.ml-slot-num` / `.ml-slot-cam` |
| `.section-title-line` | `.ml-heading-line` / `.ml-ai-badge` |
| `.price-section` / `.fee-note` | `.ml-option` / `.ml-price-rows` / `.ml-price-row` |
| `.mercari-submit` | `.ml-submit` / `.ml-draft`（フォーム）、`.ml-done-primary` / `.ml-done-secondary` / `.ml-done-text`（完了画面） |
| `.mercari-safe` | `.ml-terms` |
| `.listing-success-body` / `.mercari-success-icon` / `.listed-mini-card` | `.ml-done-screen` / `.ml-done-card` / `.ml-done-illust` |
| `.listing-scroll` | `.ml-scroll`（`.screen-scroll` との併記は維持） |

`.row-chevron`（グッズ一覧タブが使用中、`#b6aecb`）は**流用していない**。黒背景では視認できないため `.ml-chevron` を別に定義した。

## 8. state への影響

**なし。** `state.js` に新しいキーもミューテータも追加していない。使っているのは既存のものだけ。

| ミューテータ | 呼び出し元 |
| --- | --- |
| `prepareListing(itemId)` | グッズ一覧タブの[売る]／詳細モーダルの[売る]／投稿完了の[出品ドラフトを見る]／完了画面の[続けて出品する] |
| `submitListing()` | [出品する] |
| `finishListing()` | [出品した商品をみる] |
| `setRoute('assets')` | ヘッダーの×ボタン |
| `showToast(message)` | 上記 §5 の各要素 |

販売タイプのラジオは**選択済みの見た目で固定**しており、状態を持たない。オークション形式に切り替えても見せるものがないため。

## 9. 検証状況

`node --check` 全ファイル通過、参照画像の MISSING なし、Node 上で `render()` を実行してタグ対応・プレフィル・`data-submit-listing` と `data-finish-listing` が各1個であることを確認済み。グッズ一覧タブから**7アイテム全部**で入ってもフォームが生成されることを確認済み。

**ブラウザでの目視は未実施。** 実装時にブラウザを操作できなかったため。デモ前に [demo-check skill](../.agents/skills/demo-check/SKILL.md) と合わせて、次を必ず目視すること。

1. カテゴリー行の `タレントグッズ > アクリルスタンド` が折り返していないか（`.ml-row-value` は 13px。幅がぎりぎり）
2. ステータスバーとホームインジケータが黒く追随しているか
3. 選択中ラジオ（青い二重丸）が意図どおり描けているか
4. デモの核が通るか（投稿タブ → 画像選択 → 投稿 → [出品ドラフトを見る] → [出品する] → [出品した商品をみる] → グッズ一覧タブに「出品中」バッジ）

## 10. 既知の問題

**商品説明の生成が `stella-acsta` 以外で壊れる。** `js/screen-listing.js` の `description()` が

```js
'STELLIGHT ステラの公式' + item.name.replace('ステラ ', '') + 'です。…'
```

という連結のため、`stellight-hoodie` では「STELLIGHT ステラの公式STELLIGHT ツアーパーカーです」になる。

**今回の改修より前から存在するバグ**で、旧実装のロジックをそのまま移植している。デモ台本の経路（アクスタ）では正常に出るため優先度は低いが、ブースで審査員が他アイテムの[売る]を押すと見える。対応する場合は別タスクとして [../TASKS.md](../TASKS.md) に立てること。
