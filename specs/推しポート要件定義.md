## 1. コンセプト

**一言**: 一見ただの推し活SNS。投稿するだけで祭壇がポートフォリオになり、重複グッズの売り時が届き、欲しいグッズが安心して買える。裏側は全部メルカリ。

**UX原則(全画面共通)**
1. 本命グッズに売却圧をかけない。プッシュ提案は重複分だけ。売却の語彙は「手放す」でなく「**次のオタクに継承する**」
2. 金額情報(相場・総額)は本人の画面(資産タブ・通知・投稿フォーム)にのみ表示。TL・マイページ等の公開面には出さない。例外は本人が任意で生成する「祭壇カード」のみ
3. 出品はいつでもできる(アイテム単位の売るボタン常時)が、アプリから促すのは重複検出時のみ

## 2. 画面仕様

タブバー(下部固定・5つ): **ホーム / 探す / ＋投稿 / 資産 / マイページ**

### 2.1 ホーム(TL)
- Instagramフィード風。仕込み投稿 **8件**(自前グッズ写真×架空ユーザー)
- 投稿カードの要素: アイコン / ユーザー名 / 画像1枚 / いいねボタン(タップで+1、ハート赤) / キャプション / **商品名タグ**(公開・金額なし)
- うち**1件は「譲ります」ラベル付き** → カード内に**「欲しい」ボタン**。タップで「リクエストを送りました。取引はメルカリのあんしん決済で行われます」トースト
- 「譲ります」投稿主のアイコンのみタップ可 → その人の簡易プロフィール(グリッドのみ、金額なし)。他ユーザーのアイコンはタップ無効

### 2.2 探す
- インスタ風3列グリッドの静的1枚。タップ不可。タブバーの完成度のためだけに存在

### 2.3 ＋投稿(デモの核・前半)
1. 画像選択(file input。デモでは仕込み画像を選ぶ)
2. 「AIが解析中…」スピナー約1.5秒(演出)
3. **AI結果カード**: 商品名 / カテゴリタグ / 状態 / **相場 ¥3,200**(参考: メルカリ成約データ)
4. **個数stepper**(デフォルト1。ユーザーが確定させる=台帳の正確性は本人が担保)
5. 「譲ります」トグル(デフォルトOFF)
6. キャプション入力 → 投稿ボタン
7. 完了画面: 「投稿しました。ポートフォリオに追加 **+¥3,200**」
8. **直後に通知カード(デモのハイライト)**: 「⚡ ステラのアクスタ、**2個目**を検出。相場¥3,200 — 次のオタクに継承しませんか?」→ [出品ドラフトを見る] → 出品モックへ

### 2.4 資産(ポートフォリオ)
- ヘッダー: **現金化可能額 ¥84,200** / 前日比 +¥2,300(+2.8%)
- **総額推移チャート(30日・Chart.jsライン)**。急騰マーカー: 「8/21 ステライト 日本ツアー発表 **+18%**」
- アイテム一覧(行): サムネ / 商品名 / **個数** / 現在相場 / 騰落率(±%色分け) / **[売る]ボタン常時**
- 重複アイテムに「×2」バッジ(オレンジ)
- 急騰アイテム1件のみ行タップで詳細モーダル(個別価格推移チャート+売るボタン)。他はタップ無効
- 出品済みアイテムには「出品中」バッジ

### 2.5 マイページ
- Instagramのbio欄風: アイコン / りな @rina_oshi / bio「ステライト箱推し🫶 継承はDMじゃなくてここから」/ 投稿グリッド
- 金額表示なし(原則2)
- **[祭壇カードを作る]ボタン** → モーダル: 祭壇写真+「My祭壇 ¥84,200」+推しポートロゴのシェア画像プレビュー+「Xでシェア」(押すとトーストのみ)。グロースの絵として録画の締めに使う

### 2.6 出品モック(メルカリ風・アプリ外画面)
- メルカリ配色(赤#FF0211系)ヘッダー「メルカリに出品」で、推しポートから“外に出た”ことを視覚的に示す
- **全項目プレフィル済み**: 写真 / 商品名 / カテゴリ / 状態 / 説明文(AI生成風の自然な文) / 販売価格 ¥3,200(相場から自動)
- [出品する] → 完了画面「出品しました🎉 売れたら売上金は推しポートに反映されます」→ 資産タブに戻ると該当アイテムに「出品中」バッジ

### 2.7 チュートリアル(初回起動フロー)
1. ようこそ画面(コンセプト1枚: 「その祭壇、いくらか知ってる?」)
2. 「祭壇を撮ってみよう」→ 仕込みの祭壇写真 → 解析アニメ → **認識結果リスト(7アイテム)**: 各行に商品名 / 相場 / **個数stepper**
3. ユーザーが個数を調整(デモでは1箇所だけ2に直す→「手で確定させる」思想を見せる)
4. 「あなたの祭壇は **¥81,000** です」→ 資産タブへ着地

## 3. 仕込みデータ設計

### 3.1 撮影リスト(最優先タスク。誰かのグッズ棚で撮る)
| # | 素材 | 用途 |
|---|---|---|
| 1 | 祭壇/棚の全景 1枚 | チュートリアル入力 |
| 2 | 単品グッズ 7枚(アクスタ・トレカ・缶バッジ・ぬい等、手持ちに合わせて) | 資産一覧サムネ+TL投稿 |
| 3 | **同一アイテムをもう1枚別アングルで**(2個目役) | デモの投稿フロー入力 |
| 4 | 撮影時メモ: 各グッズの実際の名称 | data.jsの商品名を現物に合わせて調整 |

写真は自前品なのでそのまま使用OK。**テキスト(キャプション・イベント名・グループ名)は全て架空名に置換**: グループ名「**ステライト(STELLIGHT)**」、メンバー「ステラ」他。現物の印字が写るのは許容(私物の写真であり出品写真と同じ扱い)。

### 3.2 data.js スキーマ
```js
const ITEMS = [ // 7件+デモ投稿分1件
  { id, name, thumb, marketPrice, count, trend7d, history30d: [..], status: 'hold'|'listed', duplicate: bool }
];
const POSTS = [ // TL仕込み8件
  { id, user, avatar, image, caption, likes, tags: [itemName], giveaway: bool }
];
const USERS = [ { handle, name, avatar, tappable: bool } ]; // 架空6人
const AI_RESULTS = { // 画像ファイル名 → 認識結果(フォールバックの本体)
  'saidan.jpg': [ {name, price, count:1}, ... ×7 ],
  'acsta2.jpg': { name:'ステラ アクリルスタンド', price:3200, tags:[..], state:'未開封' }
};
const EVENTS = [ { date:'8/21', label:'ステライト 日本ツアー発表', impact:'+18%' } ];
```

### 3.3 数値の整合(この数字で固定)
- チュートリアル後の総額: **¥81,000**(7アイテム)
- デモ投稿で +¥3,200 → **¥84,200**(資産タブ表示と一致させる)
- 2個目検出対象: ステラのアクスタ(チュートリアル時1個→投稿で2個)
- 急騰アイテム: ステラのトレカ(30日で+18%、イベントマーカー付き)

| 担降りって頻繁に起きる? | 個人では低頻度でも市場では常時発生。平時は重複グッズの日常整理が利用を支える |

## 6. 技術構成

- ファイル構成:

```
index.html
styles.css
data.js            # §3の仕込みデータ(ITEMS/POSTS/USERS/AI_RESULTS/EVENTS)
assets/img/        # 撮影した自前グッズ写真
js/
├── state.js       # 状態とデータ更新(インメモリ。個数・総額・出品状態の変更は全てここ経由)
├── router.js      # 画面遷移(タブバー制御+画面表示切替。最後に読み込み、起動も担当)
├── screen-home.js     # ホームTL+探す静的グリッド+簡易プロフィール
├── screen-post.js     # 投稿フロー(AI結果カード→個数stepper→2個目検出通知)
├── screen-assets.js   # 資産タブ(チャート+一覧+詳細モーダル)
├── screen-mypage.js   # マイページ+祭壇カードモーダル
├── screen-tutorial.js # 初回チュートリアル3画面
└── screen-listing.js  # メルカリ風出品モック
```

- 読み込み順(index.htmlのscriptタグ順で固定): `data.js` → `state.js` → `screen-*.js` → `router.js`
- **ES modules不使用**(file://直開きでCORSエラーになるため)。素の`<script>`タグ+グローバル名前空間で、各screenファイルは`Screens.home = {render()}` 形式で登録し、router.jsが呼ぶ
- 各画面は「render関数がHTML文字列を返し、routerがコンテナに差し込む」方式で統一。画面間の直接参照は禁止(state.js経由のみ)→4人で並行編集しても衝突しない
- CDN: Tailwind + Chart.js。**ビルドなし**。状態は全部インメモリ(リロードでリセット。録画デモなので問題なし)
- スマホ枠: 390×844 の自前ベゼル(CSS)を画面中央に。DevTools不使用
- `gemini.js` は作らない。Gemini検証は開発中にGeminiアプリ/AI Studioへ自前写真を投げて認識結果を確認→ **スクショ保存(Q&A用)** →結果を`data.js`に焼き込む
